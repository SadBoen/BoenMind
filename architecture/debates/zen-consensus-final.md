# Zen Consensus 终局合成

Zen Consensus 跨裁决终局合成(§17 五条核心裁决)

## 总体结论

§17 五条裁决全部成立但成色不同:R1(Registry/Broker/Bus 三权分立)以最高共识(10:4)获有条件维持,是本届唯一稳固支柱;R2–R5 均判修订,但方向无一被推翻。修订焦点高度集中于"边界的精确位置":Butler 协调权与 Broker 仲裁权的分界、L0 控制面的最小职责、L2 规范状态与任务板投影的一致性、内核最小机制集的封顶。R3 共识最低(7:4),独立控制面的成本与"谁来升级升级器"的自举悖论是最大争议源。辩论揭示三大结构性张力:其一,权力分立与协调效率互斥——三权分立绝对化会使 Butler 瘫痪,须以合同式授权换取弹性;其二,极简内核与治理完备互斥——万物皆插件要求内核最小化,但条件执行、generation 回滚本身必须由可信机制承载;其三,唯一真源与投影时效互斥——L2 单一规范状态意味着任务板天然滞后,需事件水位协议显式管理。全部 33 项条件构成修订主线:权限合同化、动作可审计、升级可回滚、投影可追踪。骨架已稳,血肉待补。

## 跨裁决张力与未决问题

- R1×R2:Broker 的仲裁权与 Butler 的协调权边界模糊——协调中的资源调配何时构成越权仲裁,裁决后仍缺可执行判据
- R3×R5:L0 独立控制面与'万物皆插件'正面冲突——L0 若是插件则自举循环,若非插件则破例于极简内核原则
- R4×R1:任务板投影依赖 Bus 事件语义,但事件丢失或乱序时的投影修复责任(重放权归 Broker 还是 L2)未决
- R2×R4:Coordinator 作为受限队长需驱动任务,而任务规范状态在 L2——队长对任务板的可见写操作是否构成对规范状态的旁路,权限清单粒度未定
- R5 内部:内核'最小机制集'未封闭枚举——合同校验、generation 回滚、条件审计是否属于不可插件化机制,各模型主张不一
- R3 内部:Runtime generation 回滚的触发权归属(自动阈值 vs 人工审批)与 L0 控制面自身失效时的回滚路径未经演练验证
- 跨裁决:33 项条件缺乏统一的验收标准、追踪主体与生效顺序,且条件之间可能冲突(插件化要求 vs 可信机制内聚),需元层裁决协调

## ADR 计划

### ADR-0001 Registry/Broker/Bus 三权分立

- status: accepted-with-conditions
- decision: 确立 Registry 管注册与发现、Broker 管仲裁与路由、Bus 管事件投递的三权分立架构,任何一方不得侵入他方职责。Registry 为插件与合同的唯一事实源,Broker 只做仲裁不留存状态,Bus 只做投递不做语义解释。本条为本届共识最高(10:4)的有条件维持项,作为 §17 其余裁决的权力骨架。附 7 项条件:注册合同化、仲裁留痕可审计、事件可重放、三者间调用须走显式合同等;条件落实前不得宣称完全合规。
- sources: R1 辩论(Zen consensus 三方两轮:10 项共识/4 项争议/7 项条件)

### ADR-0002 Butler 仅持协调权,Coordinator 为受限队长

- status: accepted-with-conditions
- decision: Butler 修订为纯协调者:仅拥有任务分派、进度聚合与冲突上报权,不持仲裁权,不写规范状态。Coordinator 作为受限队长仅在 Butler 授权范围内指挥执行,越权调用由 Broker 依合同拒绝并留痕。修订要点是以合同显式列举双方权限,取代原角色描述式界定。附 6 项条件,含权限清单、越权审计与降级路径。
- sources: R2 辩论(amend:8 项共识/5 项争议/6 项条件)

### ADR-0003 L0 独立控制面与 Runtime generation 升级回滚

- status: accepted-with-conditions
- decision: L0 独立控制面原则通过,但收窄为'最小独立':控制面与数据面隔离,Runtime 以 generation 为单位原子升级与回滚。回滚触发权与控制面自身失效的恢复路径列为遗留条件,须以演练验证后方可视为闭合。本条共识最低(7:4),是五条裁决中最需后续实证支撑的一条。附 6 项条件,含 generation 链完整性校验与回滚演练节奏。
- sources: R3 辩论(amend:7 项共识/4 项争议/6 项条件)

### ADR-0004 Task 规范状态归 L2,任务板仅为投影

- status: accepted-with-conditions
- decision: 任务规范状态唯一归 L2 所有,任务板及一切运行时视图均为经 Bus 投影的只读副本,禁止任何反向写入。投影允许滞后但不允许漂移,必须携带 generation 与水位标记供一致性校验,冲突一律以 L2 为准。投影修复通过事件重放完成,重放责任归属在条件中明确。附 8 项条件,为五条裁决中最多,含投影血缘记录与水位协议。
- sources: R4 辩论(amend:9 项共识/4 项争议/8 项条件)

### ADR-0005 万物皆插件:内核只含合同与最小机制

- status: accepted-with-conditions
- decision: 内核仅保留合同体系与不可让渡的最小机制,其余能力一律插件化。最小机制集限定为注册、仲裁接入、事件投递与 generation 管理,采用封闭枚举,扩充必须走新 ADR。插件须声明依赖并遵循生命周期合同,插件故障不得传染内核。附 6 项条件,含插件沙箱边界与内核机制清单冻结。
- sources: R5 辩论(amend:9 项共识/4 项争议/6 项条件)

### ADR-0006 权限以合同显式化(元原则)

- status: accepted
- decision: 针对 R1/R2/R4 辩论共同的争议焦点,新增元原则:凡角色权限、层间边界与投影写向,一律以 Registry 注册的合同显式列举,禁止以文档描述或惯例默示授权。未列入合同的权力视为不存在,越权动作由 Broker 统一拒绝并审计。本条为相关裁决共 27 项条件的公共执行框架,使条件验收有单一判据。
- sources: R1+R2+R4 辩论交叉争议收敛产生的新增裁决

### ADR-0007 L0 自举豁免与升级信任链

- status: accepted-with-conditions
- decision: 为化解'万物皆插件'与'谁来升级升级器'的自举悖论,裁定 L0 控制面为唯一自举豁免体:其自身升级只能沿 generation 信任链回退至上一有效代,不得在线自改。豁免范围封闭枚举并冻结,任何其他组件(含其他控制面组件)不得引用该豁免。本条源自 R3 与 R5 辩论的正面对撞,是本轮辩论独立产生的新裁决。附条件:信任链根密钥管理、豁免清单定期复审。
- sources: R3+R5 辩论对撞产生的新增裁决
