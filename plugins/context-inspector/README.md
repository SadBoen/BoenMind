# context-inspector: BoenMind 官方大模型交互透视与诊断插件

> 插件标识: `context-inspector`
> 插件形态: 官方内置透视插件 (Builtin Diagnostic Surface)
> 访问入口: 主界面「上下文」双栏透视大盘 + 后端 `/admin/context` 数据总线

---

## 插件职责与边界

1. **绝对只读，零数据篡改，绝不压缩**：
   * 专注于真实上下文快照的可视化透视与诊断分析；
   * 上下文滚动摘要与压缩由后续专用 MCP 压缩插件负责。

2. **核心特性矩阵 (严守真实性原则，杜绝编造数据)**：
   * **模型窗口水位与余量倒计时**：数据源为用户在「设置 → 模型提供商」模型清单中为该模型登记的真实窗口容量（落盘于 `config/model.json` 的 `contextWindows` 表）。未登记时面板如实标注「窗口容量未登记，无法计算水位」，不做名称匹配表猜测；
   * **推理思考链透明与细分分账**：正文片段如实展示 `<think>` 思考块；Reasoning Tokens 首选提供商网关返回的真实 usage 细分，网关未细分上报时以「片段文本粗估·提供商未上报分账」诚实说明，绝不按输出比例编造假数据；
   * **提示词缓存看板 (KV Cache)**：直读网关 `prompt_tokens_details.cached_tokens`，网关未上报时显示「未上报」，网关命中时如实显示实际命中 token 数；
   * **流式首字延迟 (TTFT) 测量**：真流式模式下精确测量「请求发出至首个增量块到达」的耗时，与全程 latency 并列透明；非流式如实不报；
   * **历史对话遗忘真实告警**：后端比对「会话累计成功回合数」与「台账存活条数」（双上限 20 轮 / 24,000 字符），真实计算被裁剪遗忘的旧轮次并在界面标识，绝无无条件健康话术；
   * **工程文件读写副作用追踪 (File I/O Tracker)**：提取当前会话真实触发的 `fs.*` / `system.exec` 文件操作，按文件聚合展示最新操作（读取/写入/编辑）与参数明细；
   * **Token 暴增诊断 (Spike Diagnostics)**：相邻轮次真实 token 增量对比，智能警示外部大长文或工具返回膨胀；
   * **全域双栏联动交互**：左侧人性化大白话卡片 + 右侧专家模式 OpenAI 原始报文联动平滑滚动定位与加深高亮；
   * **一键脱敏导出 (Scrubbed Snapshot Export)**：导出服务端已做 INV-5 凭据脱敏的快照诊断 JSON 包供离线分析。
