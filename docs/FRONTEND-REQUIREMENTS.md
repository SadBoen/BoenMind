# BoenMind 前端需求（修订版 v2）

**唯一保留的前端设计需求文档。** 本文件只描述前端需求；技术实现、技术栈、代码结构由设计者自由选择，不做任何限定。

---

## 1. 产品与部署形态

BoenMind 是一款本地 agent 平台（浏览器直连本地服务）。支持两种形态：

- **Web 形态**：部署在 VPS（或本地）上，通过浏览器访问。
- **桌面形态**：加应用程序壳做成桌面程序（**Tauri**——用户俗称"traui"；Tauri 是成熟桌面壳框架）。

两种形态共用同一套前端；桌面壳（Tauri）能力在浏览器环境下必须优雅降级（不崩、隐藏或空操作）。

## 2. 功能需求（要做什么）

1. **聊天**：消息流（流式输出、Markdown 渲染、工具调用卡片）、输入区、模型选择、目标卡片（agent 正在执行的目标，可新建/编辑/暂停/恢复/完成）。
2. **会话列表**：会话列表、新建会话、搜索会话、按工作分类分组展示。
   - **会话分类用标签（tag）**。workspace 是 Agent 的工作区概念，与 Session 无关——**不得用 workspace 做会话分类**，两者不混用。分类维度 = 标签（可打可滤）。
3. **文件管理**：工作目录文件树（上传 / 下载 / 预览 / 编辑明文文本文件）、新建文件夹。
   - **下载、复制文件路径等文件操作统一通过右键弹出菜单**（不使用工具栏按钮等其它入口）。
4. **登录**：密码登录（未装配鉴权时免登录直进；装配后未登录弹登录页）。
5. **设置页**：注册/声明式可扩展的设置框架（未来 APP/SKILL/插件能挂入新设置项而不重写设置页），内置通用/模型/外观/账号/高级分区。
6. **布局骨架**：左侧窄图标导航栏 + 底部状态栏固定；主区由"单元"（可复用面板）组合而成，未来不同视图通过组合单元得到新布局。
7. **任务列表**：目标/续跑/待办的聚合展示（独立单元，可与聊天视图并列）。

## 3. 视觉需求（要长什么样子）

### 3.1 三档主题的架构（核心，扩展性最强）

三档不是三个独立皮肤，而是**两个正交维度**的组合，每一维度可独立扩展：

- **维度 A — 图标 / 装饰风格**：`卡通` ↔ `现代`（图标、贴纸、装饰元素的语言）。
- **维度 B — 材质层**：`纯色` ↔ `毛玻璃`（面板/气泡的材质）。

三档 = 两个维度各自取值后组合。具体：

| 档 | 图标/装饰风格 | 材质 | 背景 |
|---|---|---|---|
| **黑白** | 现代（中性、克制） | 纯色 | **背景不改**——中性浅色，非渐变、保持简洁 |
| **卡通** | 卡通（贴纸、几何装饰、手绘感） | **纯色（不做毛玻璃）** | 卡通图片背景 + 卡通风格图标 |
| **玻璃** | 现代（现代图标，不用卡通图标） | 毛玻璃 | 深色底 + 毛玻璃分层（默认非渐变；背景维度独立可换） |

- **卡通档"类似于玻璃效果"**：即它有玻璃那种"背景 + 浮层卡片"的分层感，但图层材质是**卡通图片 + 贴纸卡片**，**没有 backdrop-filter 毛玻璃**。
- **全设计禁止渐变背景**（本设计语言不允许任何渐变背景）。
- 玻璃档保留可调能力：**透明度（滑块）可调；毛玻璃色彩（blur 后的色相/色调）可调**。
- **背景维度独立**：默认 / 图片 / 动态（动效背景）——与三档正交，可单独替换（渐变禁用）。

### 3.2 背景与图标

- **全设计禁止渐变背景**（任何档、任何背景类型都不得用渐变——黑白的背景保持中性浅色不改）。
- 卡通档背景用卡通图片；玻璃档深色底。

### 3.3 设计一致性（系统性尺度）

**不做特立独行，但必须统一、系统化**——一致性针对**相同/同类组件元素**：同一类元素必须永远用同一套参数，不得因位置不同而取值不同；不同类元素允许有层次差异，但各自在同一系统内保持一致。

- 圆角：一套圆角尺度（如 sm/md/lg），**全局唯一**——同一类组件（如所有输入框）不会一处 50px、另一处 100px。
- 间距 / 行距：一套间距尺度（如 4/8/12/16px 阶梯），行距、内外边距都从这套取——同类文本块不出现一处 2px、另一处 10px 的随意差异。
- 字号、字体、颜色、阴影同理：全部来自统一 token 系统（设计尺度表），组件只引用 token，不写硬编码值。

### 3.4 整体视觉语言

鲜明、自洽、统一的设计取向，让人认出是 BoenMind，不是通用管理后台——但以"一致系统"为前提，不追求猎奇。

## 4. 约束

- 本地运行：无构建期后端依赖，浏览器可直连本地服务；也支持桌面壳形态。
- 唯一数据接入方式：与本地后端服务通信（具体协议由实现者对接后端源码）。
- 若实现过程中需参考后端接口，以仓库中实际存在的后端源码（`bm/web-server/` 等）为准。

## 5. Design Skills 分工（确定每个 skill 负责什么）

已安装的 design skills 分工如下，做设计/实现时按此选用：

| Skill | 角色 / 何时用 |
|---|---|
| **frontend-design**（anthropics 官方） | **设计语言总纲**：定整体视觉方向、避免模板感、主题基调（三档的"气质"）——在动手前先触发，产出设计理念。 |
| **design-system** | **token 系统**：设计尺度表（三档共用的尺寸体系：圆角/间距/字号/颜色三层 token：primitive→semantic→component）——保证一致性（§3.3）。 |
| **interface-design** | **产品界面**：登录/设置/审批弹窗/文件管理器这类功能界面布局与交互细节。 |
| **ui-ux-pro-max** | **UI/UX 参考库**：调色板、字距、UX 指南、坐标规范——查资料用。 |
| **ui-styling** | **实现层**：把 token 落成实际样式（组件 styling），如 shadcn/Tailwind 之类（若选该风格）。 |
| **impeccable** | **交付前评审**：把做好的 UI 过一遍找不统一/anti-pattern，保证 §3.3 一致性落地。 |

流程：**frontend-design（定语言）→ design-system（定 token）→ interface-design / ui-ux-pro-max（细化界面）→ ui-styling（实现）→ impeccable（评审）**。
