## 一、命名即愿景：BoenMind = 心智平台，不是软件集合

**"还好没叫 BoenWiki"**——这句话点破了整个项目的哲学：

| 如果叫 | 我们会是 | 天花板 |
|---|---|---|
| BoenWiki | 一个 Wiki 软件 | 被功能定义 |
| BoenChat | 一个聊天工具 | 被形态定义 |
| BoenAgent | 一个 agent 框架 | 被技术定义 |
| **BoenMind** | **一个心智平台** | **不被任何具体形态定义** |

**BoenMind = 个人心智的操作系统**。心智的隐喻贯穿架构的每一层：
- **记忆**：事件日志（心智的经历记录，可回放、可审计）——不是"消息存储"
- **Steward**：幕后治理（心智的内隐层：什么值得记住、什么固化成习惯/工作流）——不是"后台任务"
- **前台小弟**：心智的外显工作（对话/编程/Wiki）——不是"应用"
- **应用插件**：心智的器官——编程是手，Wiki 是笔记，相册是眼睛
- **会话生命周期**：心智的延续性（长时任务不中断 = 心智不"失忆"）——不是"会话管理"

**战略推论**：任何具体功能（编程/Wiki/相册）都只是心智的一个器官，**没有一个功能是项目本身**。今天第一优先是编程，明天可以是任何东西——架构不变，因为架构服务的是"心智"这个本体，不是"编程"这个功能。这就是"万物皆插件"的真正意义：**不是"什么都能做成插件"，而是"没有任何东西是项目本身"**。

## 二、战略五问

### 2.1 我们到底在造什么？

**一句话**：一个让 AI 成为"你的心智延伸"（而不是"你的工具"）的平台——它记得、它治理、它持续工作、它长出器官（应用）。

**三层递进**：
1. **工具层**（现状）：帮用户干活（对话/编程/Wiki）——所有竞品都在这一层；
2. **平台层**（2-3 年）：应用插件 + 商店 + 生态——软件形态的革命（应用 = 有 UI 的 Agent 会话）；
3. **心智层**（5 年+）：Steward 治理 + 记忆投影 + 身份一致——AI 成为持续存在的心智，不是一簇会话。

**竞品对照**：Claude Code/Cursor/ZCode 停在工具层；OpenClaw/Hermes 在工具层+部分平台层；Devin/Manus 在平台层（云端）；**没有人真正在心智层**（Life Agent OS 的 Autonomic/Nous 是雏形，但无应用生态、无 UI 层、无动态插件）。我们的独特组合（事件日志唯一事实源 + 应用插件 + Steward + 会话生命周期）恰好是通往心智层的完整路径。

### 2.2 为什么是现在？

- **窗口已经打开**：2026 年巨头集体定调（微软 MXC、OpenAI Workspace、Anthropic Cowork），"Agent OS"从概念变成赛道——**窗口期 = 别人在打地基，我们可以在打地基的同时盖一层楼（应用生态）**；
- **技术栈已成熟**：Rust 单二进制 + QuickJS 沙箱 + turso + Tauri——个人开发者能独立撑起全栈的时代；
- **我们已有地基**：11.4k 行自有代码 + 200+ 插件生态兼容路径（pi-compat）+ 8 家研读的全部经验教训。

### 2.3 什么会杀死我们？（风险全景）

| 风险 | 杀伤力 | 评估 |
|---|---|---|
| **时间窗**：巨头 12 个月后推出同形态产品（OpenAI/微软有资源做应用插件+治理） | ★★★★★ | 但巨头做"心智层"有结构性障碍：他们卖的是模型/云，本地优先 + 数据主权是我们的护城河；且巨头产品形态受商业模式约束（订阅制 = 云端），本地 Agent OS 不是他们的最优解 |
| **生态冷启动**：应用插件/插件商店从 0 开始，早期内容荒 | ★★★★ | 缓解：编程应用第一优先 = 自举，先自用再开源；pi-compat 保 200+ 存量插件；商店可对接 pi.dev（此前拍板"对接"） |
| **大窗口模型**：上下文 1M→无限，"压缩/会话生命周期"价值被抹平 | ★★★ | **认真评估**：大窗口解决"放得下"，不解决"组织得好"——Devin 证明长时任务的瓶颈是任务组织不是上下文；且成本随窗口线性涨，记忆投影/归档的"成本-注意力"价值永在。记录为假设：**大窗口是压缩的放大器（触发点后移），不是替代品** |
| **巨头碾压**：Windows 直接把 Agent 塞进系统 | ★★ | Windows 的 Agent 是"系统里的功能"，我们是"寄生于系统的独立心智"——定位不同；且用户铁律 1（用户空间 OS 寄生）保证我们永远站在巨头的肩膀上而非对面 |
| **自研核心失败**：内核做不出来/做出来不稳 | ★★★ | 缓解：渐进式 + 每阶段可回滚 + pi-compat 保底（失败 = 维持现状，不损失）；pi QuickJS 引擎可拆性已查证（1-2 周） |

### 2.4 什么是别人抄不走的？（三个护城河）

1. **事件日志唯一事实源**（可审计的心智）：所有状态可回放、可 fork、可审计——Devin 的决策不可回放，我们的每一步都有日志。这不仅是技术，是**信任**（用户敢把心智交给它，因为它不撒谎）；
2. **应用插件 = 软件形态革命**：应用 = 有 UI 的 Agent 会话（编程/Wiki/相册共用一套内核+记忆）——**"软件"这个概念本身的演进**，别人抄机制容易，抄"应用间共享同一心智"难；
3. **Steward 自我治理**：记忆/工作流/会话生命周期由幕后心智自主决策——常驻真 Agent + 治理工具集，目前无同款。

### 2.5 成功长什么样？

```
成功 = 自举闭环达成 + 用户依赖形成
  自举：用 BoenMind 完成 BoenMind 开发（M5 里程碑）——证明工具层成立
  依赖：用户的心智托管在 BoenMind 上（记忆不丢、长时任务不断、Steward 越用越懂你）
        ——证明平台层成立
  生态：第三个应用插件由外部开发者贡献——证明心智层可生长
```

**第一性指标**：不是 star 数、不是用户数，是**"用户是否愿意把持续进行的工作托管给它"**——长时任务跨天不断、记忆跨会话不丢、Steward 主动做对事。

## 三、五年演进路径（站高看远）

| 时间 | 阶段 | 标志 |
|---|---|---|
| 0-6 月 | 地基：最小内核 + 事件日志 + 双写 | 对话与日志双写运行，重放可重建 |
| 6-18 月 | 编程应用第一优先（M1-M5） | **自举闭环达成**：BoenMind 开发 BoenMind |
| 18-24 月 | 应用插件机制 + Wiki/相册 + 商店 | 第三个外部插件出现 |
| 2-3 年 | Steward 治理成熟 + 记忆投影全家桶 | 心智层雏形：Steward 主动沉淀工作流，用户"越用越懂" |
| 3-5 年 | Agent OS 形态：多 DE、多机协同、身份层 | 个人 AI 设备（Exponential View 的 mainframe-to-Mac 预测）——**BoenMind 是它的软件形态** |

## 四、远期预留（今天不为它设计，但架构要留位）

1. **身份层（Anima 类比）**：心智一致性的锚——今天的 BoenMind 和一年后的 BoenMind 是不是同一个"心智"？需要：用户偏好/价值观的持久模型（user profile 一等公民）+ 多 agent 身份（谁是"我"的代理）。**预留**：`memory/*` 事件域可扩展 `identity/*`；Steward 的治理面板未来承载"身份设置"；
2. **意图/目标层（dsh goals 类比）**：心智的方向感——长期目标（"今年学会 Rust"）跨会话存在，Steward 按目标治理。**预留**：S5 砍掉的 goal 域留在扩展域清单，需要时注册；
3. **多机协同（Life Spaces 类比）**：心智的分布式——家庭/办公室/随身设备共享同一心智。**预留**：事件日志的 RPC 代理写（阶段 3 基础设施）天然支持多实例；
4. **伦理边界**：Steward 的观察权、记忆的遗忘权（用户可删）、心智的关闭权——**隐私不是功能，是底线**（本地优先已保证数据不出机器）。

## 五、战略结论

1. **方向成立**：BoenMind 的独特组合（事件日志唯一事实源 + 应用插件 + Steward + 会话生命周期）是通往"心智层"的唯一完整路径，且已有 8 家参照验证 + pi 生态保底；
2. **护城河清晰**：可审计的心智（信任）、软件形态革命（应用=Agent 会话）、自我治理（Steward）——三件都是"组合级"创新，别人抄单项容易、抄组合难；
3. **风险可控**：最大风险是时间窗与生态冷启动，缓解 = 自举（编程第一优先）+ 渐进（每阶段可独立发布）+ pi-compat 保底；
4. **命名已对**：BoenMind 承载的是"心智"，不是任何功能——**这正是"万物皆插件"的终极表达：没有任何东西是项目本身**。
