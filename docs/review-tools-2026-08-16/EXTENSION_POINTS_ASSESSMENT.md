# 扩展点合理性评估 2026-08-16

> 三工具交叉审查"先建后接"主题（REVIEW_TOOLS_CROSS_2026-08-16.md 主题 1）的回应。
> **用户定调：不破坏万物皆插件理念——挂点现在没用上不代表将来不能用，软件还没写完；
> 但挂点的合理性可以评估。** 本评估只输出判定与登记，不删任何代码。

## 评估原则

1. **扩展点是生长空间**：内核/协议层的挂点与服务面是插件生态的接口，接口先于消费者是
   "先用后注册"之外的另一种合法节奏——前提是每个扩展点有**明确的接线方**（文档承诺的
   消费者、路线图里程碑或插件生态的自然接口）。
2. **合理性判据**（每项评估三问）：① 是否有接线方（文档/注释/路线图承诺）；② 维护成本
   （测试面 + 读代码负担）；③ 是否与既有机制重复（平行机制才是真债）。
3. **分级**：`合理保留`（有接线方，接口方向正确）/ `待接线`（有路线但时机未到，登记时机）/
   `建议清理`（真死代码——无任何潜在消费者，且与既有机制重复）。

## 二、EventBus（内核四件套之一，四种分发模式）

- **接线方**：A5 订阅注释自述"阶段 1 用轮询，A6 自研 loop 落位后换内核事件总线直推（无轮询延迟）"；
  bm-compactor 接线轮后总线仍未激活（2026-08-16 复核：生产零调用）。
- **评估**：`待接线`——插件事件轨（阶段 3）与前端 SSE 直推（替代 250ms 轮询）是明确消费者。
  保留；登记接线触发条件：**TS 插件域事件（app/* 事件注册）落地时**。
- 附注：`waterfall/parallel/serial` 三种分发模式目前无真实使用场景（插件事件 handler 链语义
  演进时自然出现），保留不删——删除再恢复的破坏性（插件接口兼容）大于空载成本。

## 三、LoopHooks 挂点（12 个，8 个无消费者）

- 无消费者：on_pre_step / on_request_error / on_turn_stopping / on_context_build /
  on_compact_begin / on_compact_end / on_turn_end / on_provider_select
- **评估**：`合理保留`——这些挂点全部是**回合生命周期事件**的投影点（步开始/错误/回合停止/
  上下文构建/压缩事务/回合结束/模型选择），是观察者/审计/统计类插件（记忆注入、用量统计、
  审计日志）的自然接口；默认空实现成本为零，删除再恢复破坏插件接口。
- **登记纪律**（建议）：在 HANDOFF 建"挂点消费者登记表"——每个挂点一行（挂点/消费者/用途），
  防止静默扩挂点（新增挂点必须登记，与"先用后注册"同纪律）。

## 四、declare_event! 宏（插件域强类型事件）

- **接线方**：文档 §6.3"事件域注册式插件事件"——TS 插件域事件轨（阶段 3）。
- **评估**：`待接线`——当前插件事件全走 CoreEvent 变体（todo/write 等），宏是插件域事件的
  承载设计。保留；登记：命名风格（EVENT_TYPE 用 PascalCase vs 文档 app.wiki.indexed 小写
  命名空间）在启用时对齐。
- 附注：插件事件域（app/*）是"三真缺口"之一（架构回头看 2026-08-15），本宏是其类型层准备。

## 五、队列 API（enqueue_turn / pending_turns / run）

- **接线方**：文档 §5.3/§14.2"所有回合源汇入同一队列，天然串行"（回合源三分法）。
- **评估**：`待接线`——当前串行由会话串行锁承载（P0 回看修复），队列机制未启用；
  M3 回合内注入（inject 不唤醒语义）需要队列语义时启用。保留；登记 M3。

## 结论

13 面中 9 面有消费者（含 P2-2 新闭环的 memory），4 面待接线（均有明确接线方）；
EventBus/宏/队列/fork/死契约变体全部 `待接线`（有路线图承诺或插件生态接口）；
**唯一 `建议清理` 项 = pi_name 24 路映射**（真死代码，登记待拍板）。
"先建后接"从"决策惯性"重估为"接口先行、接线有方"——但要补上**消费者登记表纪律**
（服务面/Hook 挂点/契约变体各建一行登记，新增扩展点必须登记接线方），防止未来
出现真正无主扩展点。
