## 2. 关键实现要点与坑（勿回退）

- **fork 的 seq 语义**：新会话先 `create_session`（写 SessionStarted seq=1），再逐条 append
  复制事件——seq 从 2 连续，与 `seq = log.length` 契约一致（SessionStarted 恒占 seq 1）。
- **host 基线在 mux 之外独立**：`AppState.host_events_tx` 独立 broadcast 通道，mux 事件
  不混入（前端 mux/host 双流各自消费）。
- **广播锁纪律**：workspace 写方法先 drop 锁再 `broadcast_host`（快照要重新拿锁，
  死锁风险：workspace_snapshot 拿 workspaces 锁，若持锁广播即自死锁）。
- **prompt 双广播**：开跑时 `session-status{running:true}`、tokio::spawn 结束后 false。
- **验证脚本竞态**（重要）：WS "判据即关" 会丢尾部帧（close 竞态）——用固定收集窗口
  （400ms 静默后 resolve）；create 广播帧可能先于 HTTP 响应到达——open 回调设 wid 后回扫
  已收集帧。
- **gate25 的 items[0] 假设**：gate25 断言 workspace.list 的 items[0] 是自己的 workspace——
  前置脚本先建 workspace 会导致 FAIL（脚本环境假设，非回归；全新 db 验证 15/15）。
- **fork 无完成 turn 会 fork-unavailable**：空会话 fork 是契约正确的错误（不是 bug）。
