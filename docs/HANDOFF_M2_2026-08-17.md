## 2. 下一轮任务：M2.5 前端直连 + 方法补齐

### 动手步骤
1. **前端产物组装**（关键坑：dsh 无预构建产物，M0 是 `node scripts/dsh.cjs web` 运行时组装）：
   - 研究 `packages/client/web`（dsh-web-app）如何把 bundle 交给 host 的 `frontend-static` 服务；产物可能需 `pnpm build`（tsc -b + tsdown，根 package.json 有 `build:web`）。
   - 目标是拿到一个静态目录（index.html + assets/ + 各 /plugins/*/client.js bundle），`web-server --dist <该目录>` 直接喂。
   - **boot 槽缺口**：Rust 兼容层当前注入 `__DSH_BOOT__={rev,entries:[]}` 空清单——前端需要真实的 entries（各插件 bundle url + rev）才能拉起插件。研究 `WebBootGraph` 组装逻辑（packages/client/modules/src/index.ts injectBootManifest + dsh-base 的 composition），要么从 Node 后端抓一份真实 boot manifest 存 fixture，要么实现简化组装。
2. **RPC 方法补齐**（52 方法，当前 13 个实现）：按台账 §2 逐组补 workspace.*/goal.*/skill.list/agentPresets.*/subagent.*/llm.discoverModels/session.* 剩余/settings.* 写面/credentials.* 写面/host.* 目录面。每补一组，录一批 Node 轨迹进 conformance 并重跑 diff。
3. **WS 下行基线**：mux 流的 `session/subscribed` 基线（lastSeq）+ 重连重放，当前只有 live 帧。host 流 `host/session-added`/`host/session-status` 基线。
4. **respond 双向**：approval/question pending 表（台账 §1 面 7 的 accepted 三分支）。
5. **提交**：新仓 main；自查 cargo test/clippy + conformance diff。
