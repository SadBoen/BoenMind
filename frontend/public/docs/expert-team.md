# 专家团队（Expert Team）功能描述与设计构思

> 状态：构思阶段（2026-08-13）。本文档是专家团队功能的唯一描述载体，持续迭代。
> 近期构思会陆续补充进本文档，实现按"分阶段落地路线"推进。

## 一、功能定位

在 BoenMind 中引入"专家团队"：用户不是与单个助手对话，而是组建/选择一个**团队**，向团队提出任务；团队由多个各具专长的 **Agent（专家）** 组成，在**队长**的组织下分工协作完成任务。

```text
用户任务
  └─▶ 队长 Agent（规划、派工、汇总）
        ├─▶ 专家 A（角色 prompt + 模型 X + 技能集 A）
        ├─▶ 专家 B（角色 prompt + 模型 Y + 技能集 B）
        └─▶ 专家 C ……
```

## 二、需求要点

1. **团队维度**：进入功能后可以选择不同团队，例如**办公团队、炒股团队、养生团队**——团队是角色的集合与场景容器。
2. **角色定义**：每个团队可定义任意数量的 Agent，每个 Agent 独立配置：
   - 接入哪个模型（可与其他 Agent 不同）
   - 角色身份标签（角色 prompt：我是谁、擅长什么、说话风格、行为准则）
   - 擅长的技能（技能系统需演进为**技能池**，按 Agent 分配）
3. **数据传递与隔离**：团队成员之间既可以**传递数据**（任务上下文、中间产物），也可以**隔离数据**（保密任务、互不干扰）——由**队长的安排**决定。
4. **参考项目**：https://github.com/EKKOLearnAI/hermes-studio —— 其"多代理聊天室（实时消息、@-mention 路由到指定 agent）+ 每 Agent 独立 profile（模型/技能/prompt）+ 可视化工作流编排"值得借鉴；但 BoenMind 的团队形态不必照搬聊天室，先以"队长编排"落地。

## 三、设计构思

### 3.1 团队模型

```text
Team（团队）                     # 办公 / 炒股 / 养生 …
├── name / description
├── manager（队长配置）           # 默认主 agent 充当，可指定角色
└── agents[]（专家列表）
     ├── name / role_prompt      # 角色身份标签（system prompt）
     ├── model                  # 接入的模型（跨 provider）
     ├── skills[]               # 从技能池分配
     └── visibility             # 数据可见范围（共享 / 私有 / 白名单）
```

- 团队配置 = BoenMind 业务层数据（配置文件或 DB），与 pi 的 `agents/*.md` 角色定义对齐，可互相导入导出。
- 预置团队：办公、炒股、养生（开箱即用 + 用户可自定义）。

### 3.2 技能池

现状：BoenMind 的 skills 是"全局启用列表 → 注入 system prompt"（`enabled_skills` → `skills_prompt`）。

演进方向：

```text
技能池（全局技能库：backend/skills/* + 用户技能）
   └─▶ 团队/Agent 分配（skill assignment）
          └─▶ 运行时按成员注入（角色 prompt 携带其技能说明）
```

- 技能仍以现有 SKILL.md 体系存储，新增"分配"关系（哪个 Agent 用哪些技能）。
- pi 侧已具备 `agent 定义 → skills 字段`（`subagents.rs` 解析，相对定义目录解析路径），BoenMind 做技能池管理（UI + 配置）即可打通。

### 3.3 协作模式：队长编排（阶段 1 形态）

- **队长 = 主 agent**（system prompt 注入团队编队 + 协作协议：规划 → 派工 → 收结果 → 汇总）。
- **专家 = 子代理**（pi `subagent` 工具，进程级隔离，天然满足"数据隔离"）。
- 派工形态（pi 原生支持）：
  - **Single**：单个专家干一件事；
  - **Parallel**：多个专家并行干活（最多 8 个，默认并发 4）；
  - **Chain**：顺序链，前一步输出 `{previous}` 传给下一步（如：调研 → 分析 → 出报告）。
- **数据传递**：共享工作区文件（专家有 read/write/bash 工具）+ 队长中转（把上下文写进任务文本、把结果带回）。
- **数据隔离**：子代理天然隔离（互不可见、默认无 subagent 工具防递归委派）；"保密任务"通过私有目录/权限实现。

### 3.4 协作演进（阶段 3+，可选）

- 代理间**直接对话/协商**（hermes 聊天室语义）：需要 BoenMind 自建"协作通道"——消息队列文件（专家轮询）或插件消息总线（hostcall 桥），队长按任务动态开放/关闭通道。
- 团队级"黑板"（共享上下文区）与可见性控制。

## 四、架构评估：能否在 pi_agent_rust 基础上实现？

### 4.1 结论

**没有本质架构冲突，可以在当前 pi_agent_rust 基础上实现。** pi 的"单主循环 + 工具系统 + 子进程委派"架构本身就是"队长-员工"模型的天然表达；团队、技能池、数据传递均为 BoenMind 业务/编排层工作，无需改写 pi 核心。

### 4.2 需求逐条对照

| 需求 | pi_agent_rust 现状 | 评估 |
|---|---|---|
| 团队（多角色集合） | 无团队概念；有 `agents/*.md` 角色定义（name/description/model/reasoning/tools/skills + 正文=角色 prompt，`subagents.rs:438-475`） | ✅ 团队 = BoenMind 层配置（角色文件集合），无冲突 |
| 每 Agent 接不同模型 | 子代理支持 `--model` 参数；BoenMind 已有多 provider 体系（config.toml） | ✅ 原生支持 |
| 角色 prompt | agent 定义正文 = system prompt；BoenMind 有 SYSTEM_PROMPT + skills 注入机制 | ✅ 原生支持 |
| 技能池 + 按 Agent 分配 | agent 定义 `skills` 字段已存在（`subagents.rs:446-460`）；BoenMind 现有 skills 注入 | ⚠️ 需做技能池管理与分配（业务层），pi 侧机制已就绪 |
| 数据传递 | Chain 模式 `{previous}` 传前一步；共享工作区文件（专家有 read/write/bash）；队长中转 | ✅ 用现有能力组合实现 |
| 数据隔离 | 子代理进程级隔离、互不可见、默认无 subagent 工具（`subagents.rs:221-226`） | ✅ 原生特性 |
| 派工编排（规划/并行/链式） | subagent 工具 Single/Parallel(≤8)/Chain；主循环支持多轮工具迭代 | ✅ 原生支持，队长循环天然成立 |
| 代理间直接对话 | **无**（上游在外部 Agent Mail MCP 服务，BoenMind 未引入） | ⚠️ 需自建协作通道（可选演进，非阶段 1 必需） |
| 协作 UI（团队管理/会话视图） | 无 | ✅ 纯前端工作 |

### 4.3 关键架构事实与边界

- **子代理是子进程**：spawn 当前可执行文件（= bm-server 二进制）+ `--mode json --print --no-session`，stdout JSON 事件流回传。BoenMind 需补"子代理入口子命令"（bm-server 目前不认识这些参数）——这是启用 subagent 前的唯一前置工作，vendor 无需改动。
- **深度上限 3**：子代理默认不带 subagent 工具（防递归），工具白名单可在角色定义中覆盖——团队内若需"再分层"需显式放开并受深度限制。
- **Chain 的 `{previous}` 只能引用前一步**：多步依赖的复杂流程由队长（主 agent）通过多轮工具调用编排，而非内置 DAG。
- **无运行时消息总线**：代理间直接通信需自建（消息文件/插件通道），上游不提供进程内实现。
- **Provider 解析**：子代理子进程需自己解析 provider（BoenMind 配置全局默认 + 角色定义 model 匹配），可复用 bm-core 现有 ProviderConfig 体系。

### 4.4 风险与注意点

- 并发成本：并行专家 = 多个 LLM 流 + 多个子进程，注意配额与 token 成本（可限制并行度）。
- 数据隔离边界：子代理有 bash 工具（与主 agent 同权限），"保密"是工作区约定而非强沙箱——如需强隔离需另做权限控制。
- 多模型一致性：各专家模型不同，输出风格/能力差异由角色 prompt 收敛。

## 五、分阶段落地路线

- **阶段 0（本次）**：左侧导航"专家团队"入口 + 本文档（规划载体）。
- **阶段 1：队长派工基础**——启用 subagent 工具（bm-core 一行）+ bm-server 子代理入口子命令 + 预置示例角色定义（agents/*.md）。交付"主 agent 可派工给角色化子代理（single/parallel/chain）"。
- **阶段 2：团队管理**——团队 CRUD（预置办公/炒股/养生）+ 角色配置 UI（模型/角色 prompt/技能分配）+ 技能池化改造。
- **阶段 3：数据传递/隔离机制**——团队工作区规范 + 队长编排协议（何时共享、何时隔离）+ 协作通道（按需）。
- **阶段 4（可选演进）**：代理间直接对话/协商（消息总线），对标 hermes-studio 聊天室形态。
