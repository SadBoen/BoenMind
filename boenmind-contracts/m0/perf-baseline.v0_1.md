# BoenMind 性能与资源基线定标（M0.6 骨架）

> 版本 v0_1（2026-08-28 定标）。
> 落实基线 §18-M0.6「性能与资源基线定标」。定标原则：**M0 只定义指标与测量方法，
> 数值由 M1 以 mock 模型回填**；回填后本文件即成为后续每个里程碑回看（§19-G）的
> 回归基线。禁止拿联网真实模型跑分（外部方差不可控），一律用可注入延迟/长度的 mock。

## 1. 指标定义（P-01..P-10）

| ID | 指标 | 定义 | 测量方法 | 目标（待 M1 回填） |
|---|---|---|---|---|
| P-01 | 冷启动到 ready | 进程启动 → Wire API 可接受 session.create 的墙钟时间 | 50 次取 p95 | **p50=0.100 / p95=0.124 ms**（M1 回填①） |
| P-02 | Session 恢复 | 含 1 万条持久事件时 session.resume 完成（投影/位点就绪）p95 | 预置事件库，20 次取 p95 | **p50=23.78 / p95=25.87 ms**（M2 回填②） |
| P-03 | 单 Agent 回合延迟 | send_input → 执行收据落盘；mock 模型固定注入 200ms 延迟 | N=100 回合，取 p50 / p99 | **p50=223.1 / p99=236.9 ms**（M1 回填①；注入 200ms,自身开销≈23ms,含 2ms 收据轮询量化） |
| P-04 | 事件追加吞吐 | 持久事件日志单写者追加速率（含落盘） | 批量 1 万事件计时 | **106 条/s**（M2 回填②;每条 fsync+物化+位点 CAS,Windows fsync 昂贵,如实记录） |
| P-05 | 事件回放速率 | 从空库重放到 1 万事件完成 | 计时 | **580,245 条/s**（M2 回填②,内存速度:重放不含 fsync） |

| P-08 | 脱敏扫描开销 | 每条日志记录的脱敏扫描平均耗时 | 微基准 N=10 万条 | **2.715 µs/条**（M1 回填①,内存模式） |

| P-10 | 队头阻塞注入 | 50ms 慢 Provider 在册时,无关授权决策(纯查表)的 p99 相对空闲基线劣化 | 注入对照 N=500(M4 规格 §5.1 证伪测试②) | **零劣化**(M4 回填③:基线 0.200 / 在册 0.200 µs,门 2×) |

## 2. 测量方法学（所有指标通用）

```text
环境:  记录机器档位(CPU/内存/盘)、OS 版本、提交号——回填数值必须附带环境元数据
负载:  mock 模型(无外网);输入固定语料;关闭无关后台任务
次数:  延迟类 N=100、吞吐类固定总量计时;先丢弃前 10 次预热
口径:  墙钟以单调时钟计(基线 8.3);时间戳仅参考
复跑:  每个里程碑回看重跑全部已回填指标,结果写入回看记录(§19-G)
```

## 3. 回归门槛

- 任一已回填指标相对上一次基线**劣化 > 25%** → 触发架构回看，给出解释或回炉项。
- 新增指标 = 追加 ID；既有 ID 定义不得改（与合同冻结纪律一致）。
- 目标值回填动作发生在 M1 里程碑回看；回填后此文件进入只增不改状态。
