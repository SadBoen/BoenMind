# ADR-0013:弃用 dsh 复刻 Web 前端,换新参考界面重做

- 状态:已裁决(用户 2026-08-31);新参考界面待用户指定后另行入册
- 裁决人:用户(原话「算了,你把全部的Web前端删除吧,我们抄另一个界面」)
- 编号说明:ADR-0012(配置管理 API)随 M10 未提交工作归档于
  `archive/m10-dsh-frontend` 分支,主干跳过该号

## 背景

2026-08-30 起 Web 前端整体复刻 dsh 官方 Web(MIT):dist 构建产物 +
42 个官方界面模块 + cordis 槽位系统 + 静态化 `__DSH_BOOT__` 清单。
经五轮用户实测迭代,对话闭环/模型配置/工作区创建等主链路先后打通,
但用户可见面持续反复受阻:

- 目录选择器(交互 13)自第一版起从未真正可用:官方实现走 host 原生
  对话框(单机形态不可用)→ 改文本输入弹窗 → 重写为双栏悬浮面板,
  三版均未在浏览器中真正上线;
- 前端为压缩分发的第三方构建产物,问题定位依赖逆向(槽位声明、fiber
  服务门禁、boot 清单 rev 缓存键层层叠放),单问题排查以小时计;
- 静态资源无缓存头 + rev 键不随内容更新,浏览器咬旧插件文件,「改了
  不生效」与「从未生效」难以区分。

2026-08-31 用户裁决放弃该路线,换一个更可控的参考界面重做。

## 裁决

1. **runtime/web 全量删除**(主干提交 32d44b9,137 文件 -79,369 行)。
2. **M10 未提交工作全量归档**于分支 `archive/m10-dsh-frontend`
   (97596a1):api_dsh 第三批(listDirectory 目录标记/crumbs 层级)、
   config_store 配置 CRUD、ADR-0012、M10 规格与实测台账、面板重写版。
   分支不合并、不删除,随时可翻。
3. **后端保留不动**:/rpc 合同面、api_dsh 宿主协议适配器(事件流/
   会话/工作区)、/api/config.* 配置管理、审批/任务等全部服务不变;
   新前端直接复用,合同零变更。
4. m8 t120 静态面断言降为占位页口径(自建临时页),静态托管能力
   (T6a)与鉴权面测试不变。

## 后果

- 正面:前端黑盒调试成本归零;新界面可从零控制;后端合同面经过
  M1-M10 已充分稳固,前端重做不触碰合同。
- 代价:dsh 线五轮迭代作废(已归档);「配置 CRUD/对话闭环已打通」
  的用户可见面退回不可见状态,随新前端重新交付。
- 后续:新参考界面由用户指定(候选评估属用户裁决项),选定后按
  「先入册再动工」流程发规格;接入前 `GET /` 无前端(服务器启动
  不带 `--web-dir` 即纯 API 形态)。
