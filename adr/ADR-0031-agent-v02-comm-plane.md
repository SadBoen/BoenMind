# ADR-0031: Agent v0.2 通信面——消息语义架于进程内事件总线,成员级身份

- 状态: Accepted（用户 2026-09-09 拍板:①通信形态取「信件语义+进程内总线」折中;②信任模型取成员级身份并与 #31 合并一次 ADR;③远程网格留阶段二。实施另行排批,规格先行过目）
- 日期: 2026-09-10
- 关联: ADR-0002（Butler/Coordinator 受限队长）、ADR-0006（权限以合同显式化）、基线 §11（协作路径）、issue #45（本条为其决策文档）、issue #31（成员级 max_concurrent_tools,随批次 2 落地）、issue #36（抽屉规则合同化,时点随批次 2）、issue #53（hermes-webui 调研）

## 背景

v0.1 协作是纯树状（基线 §11 / ADR-0002）：信息只能沿「Worker → Coordinator → Worker」流动，成员之间无通信面——A 成员的发现 B 成员不可见，一切共享须经 Coordinator 收集再派发。信任归因为 per-task principal（`agent:worker:{task_id}`，team.rs），同一 Task 全体 Worker 共享、无成员级身份（#31 查明）；worker_call 单写者同步出结果时成员并发在途恒 ≤1，M9 worker 自主环 v0 落地后开始出现独立调用流。

用户指定参考 nesquena/hermes-webui（#53）：其前端把 agent 内核 in-process 直接 import，版本锁死、容器拆不开，官方以 #1925/#2491 追「稳定 Agent API 边界」——反面教材佐证本仓库「合同先行、Surface 不触内核」路线，架构面不参考；产品交互面入 #53 参考池随用随取。

用户拍板（2026-09-09）：形态折中 + 成员级工牌 + 远程后置（详见决策）。

## 决策

1. **通信面 = 消息信封语义,载体 = 既有单写者事件总线**。成员间通信按结构化消息建模（类型化、可点名、Task 子树作用域），消息即事件、经内核循环分发——单写者纪律（事件序单调）与 Broker 裁决管线全覆盖，不新增第二通信通道。信封保留作用域/路由字段，阶段二若上远程网格只换传输不改信（超出预留字段再发 ADR）。
2. **信任模型 = 成员级身份（每人一张工牌）**。worker principal 演进为带成员段形态（具体段格式随批次 2 规格冻结），wire 面增成员归属字段（合同 Minor）；Broker Grant audience、审计归因、预算账本按成员记。#31 的成员级 `max_concurrent_tools` 随批次 2 一并落地，计数点 = worker_call 成员在途。
3. **范围分期**。批次 1 = 共享面（公告栏）：Task 作用域共享发现板，成员可在干活途中发布/查询发现；不点名、不发新工牌、零信任语义变更，先行可做。批次 2 = 点名消息 + 成员身份面（决策 2 落地），与 #31 合并实施。远程网格 = 阶段二后续。
4. **生命周期与隔离沿用既有语义**。消息作用域绑定 task:<id>，跨 Task 结构性不命中（per-task principal 同款）；Task 终态其消息面随之失效；审计粒度到成员（批次 2 起）。

## 后果

- 单写者纪律不破：通信面零新增旁路，Broker 审计全覆盖。
- 批次 1 无信任语义变更，可在现行 per-task principal 上先行；批次 2 触 Broker 信任归因，实施以本条为 ADR 依据。
- 审计与预算到成员（#31 字段），成员行为可归因、可限流。
- 公告栏噪音以 Task 子树作用域天然隔离，无跨 Task 泄漏面。
- #36（抽屉规则合同化）与批次 2（成员记忆域演进）同批，避免单独动 Broker 裁决步。
- 实施规格见 `milestones/`（开工入册，交付即删，ADR-0027）；批次 2 动工前先核成员真并发成熟度（M9 自主环 v0 现状）。
- 收口时熔入基线 §11 正文并标注本 ADR；`docs/architecture/decisions.md` 评估增条（15 条上限，届时淘汰最久未撞条目）。
