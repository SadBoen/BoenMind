# ADR-0005 万物皆插件:内核只含合同与最小机制 
- 状态: accepted-with-conditions - 日期: - 决策类型: 架构裁决(对基线 §17 裁决 R5 的复核结论) 
## 背景(原裁决文本) 
> 内核只由合同与最小机制组成;模型连接器、记忆引擎、定时器、评价器、Secret Store 都是扩展点上的普通 Provider,不是内核特权组件;新增功能默认走插件路径,只有既有扩展点无法表达才允许改合同,并按 §13.5 升级级别处理。 
## 裁决(决策要点) 
1. 内核只由合同与封闭清单化的最小机制组成：Capability 裁决、引导信任根、持久事件日志单写者与 event_seq、双代际写入租约与栅栏、Operation/Approval 状态机、L0 监督单调时钟；新增任何内建机制必须逐项通过安全不变量四判据（写全局权威状态、需单调可信时间或全局序列、参与启动信任根或凭据版本、须与 Operation 结果原子提交）并给出「为何不可做成 Provider」的证明，清单变更按 §13.5 处理。 2. 模型连接器实现、可重建记忆索引、评价器、业务定时器（Cron/提醒/计划任务）默认以普通 Provider 身份注册于扩展点，新增功能默认走插件路径，不设内核特权实现；「万物」指功能能力层，不含底层存活与不变量机制。 3. 安全不变量由内核最小机制强制执行，Provider 只是租约持有者与合同履行者，不得自行决定写入协议、提交栅栏、可信时间与恢复语义；恢复以语义连续为目标（行1263），outcome_unknown 一律先核验外部系统、不自动重放。 4. L0 监督时钟与业务定时严格分层：监督 watchdog 与 L2 Operation 超时为内核内建单调时钟机制、不依赖外部 IPC、不可插拔；业务定时能力为可替换 Timer Provider，二者禁止混同表述。 5. Secret 存取采用「内核 Secret Broker 最小机制＋可替换 Secret Engine Provider」两层结构：内核持有根密钥引用、会话凭据版本锁与凭据版本栅栏；引擎 Provider 的热替换合同必须内置凭据同步握手、版本租约转移与审计日志连续性语义，不满足者由内核栅栏拒绝切换。 6. 改合同实行双重门槛：表达性测试（既有扩展点语法不可表达）与不变量保持测试（包装为 broker.call 后仍无法维持全局序列、可信时间、凭据版本、恢复语义）须同时成立，方按 §13.5 升级级别处理；不得以「可包装为 broker.call」拒绝必要的合同演进，也不得以包装规避不变量归内核。 7. 无特权通道为强制纪律：第一方与第三方组件同等经 manifest 声明＋Broker 裁决，Execution Log 不存在不可记录、不可回放的调用路径；举证责任恒在「增加特权」一方，交付压力下绕过举证义务须作为 §13.5 级事件留痕并触发架构评审。 8. 阶段一进程内实现必须第一天按 Provider 边界设计，并以 M3（模型连接器外置为独立进程、调用方与记账零感知）、M7（签名从来源标识升级为完整性验证）及「跨代热替换经写入栅栏证明无未决 outcome_unknown 孤儿副作用」为可证伪验收；任一未通过即复审对应能力的 Provider 化判定，阶段二迁移因此降为部署拓扑变更而非 Major 级系统升级。 
## 条件与验收 
- 内核最小机制实行封闭清单管理（Capability 裁决、引导信任根、事件日志单写者与 event_seq、代际写入租约与栅栏、Operation/Approval 状态机、L0 监督单调时钟），新增项必须逐项通过安全不变量四判据并留有「为何不可做成 Provider/App」的书面证明；清单变更按 §13.5 升级级别处理。 - 承载安全语义的 Provider 设置注册门槛：其合同必须内置健康检查、超时、轮换、凭据版本与 outcome_unknown 外部核验/对账语义（KMS v1 教训），缺任一项不得注册生效。 - 行197 举证义务制度化执行：每次内核增长留痕可审计，交付压力下不得绕过；任何事实松绑（绕过 Broker 的内部通道、未走 §13.5 的合同变更）须作为 §13.5 级事件记录并触发架构评审。 - M3/M7 可证伪验收按时执行：M3 模型连接器从 L2 进程内迁出为独立 Provider 且调用方与记账零感知；M7 签名从来源标识升级为完整性验证；跨代热替换（§13.4）须以写入栅栏证明未产生未决 outcome_unknown 孤儿副作用——任一未通过即触发「纯 Provider 模型不足以支撑该关键服务」的裁决复审。 - 记忆引擎 Provider 只能实现为可从权威事件日志重放重建的下游索引，不得持久持有唯一真相；其崩溃与热替换的恢复路径定义为日志重放。 - 合同演进治理常态化：L1 演进全部走 §13.5、可回滚、原因可追溯至双重测试的证明；预期首年至少一次 Minor 演进，若零演进须审查扩展点是否被教条压制。 
## 开放问题（未决；供里程碑回看时审视） 
- **不变量执行载体的表述归属**：是否需在「合同＋最小机制」之外单列「受保护控制面」范畴（Secret Store／Event Store／权威 Scheduler 的写权限、版本租约、事务边界、恢复证明归内核），还是由现有合同与栅栏覆盖。 - **凭据版本裁决权的归属**：凭据版本栅栏是内核强制机制，还是 Secret Store Provider 的合同义务＋内核校验；直接决定 draining 窗口凭据错乱由哪一层防御。 - **权威 Scheduler 与可信 deadline 的归属**：业务调度的截止时间／重试／审批是否构成需内核可信 deadline 背书的跨 Task 安全语义（基线相关条款存在文本冲突）。 - **「零特权通道」的长期可持续性**：无先例的激进治理纪律在真实需求压力下能否长期执行，只能以可证伪验收与制度条件约束，不可判定。 
## 后果 
- 本 ADR 并入后,基线 §17 对应裁决以本文件为准;条件的验收责任落在对应里程碑(条件中已注明 M2/M3/M4/M7 等)。 - 条件全部闭合前,该裁决对外宣称口径为「有条件成立」;任一验收被证伪即触发本 ADR 复审(而非默认回退)。
