# ADR-0026: 文档纪律——规范与叙事分离(评审上下文减负)

- 状态: Accepted(用户 2026-09-08 裁决「文档不组织好,项目走不动」并批准重组方案)
- 日期: 2026-09-08
- 关联: ADR-0015(文档体系整理,本 ADR 细化其执行纪律);对标 = pi_agent_rust 的 AGENTS.md 写法(全文操作规范、零编年史,历史隔离于 CHANGELOG/UPGRADE_LOG 专用文件)
- 背景: 2026-09-08 诊断实锤——评审/回头看必读路径(AGENTS→基线→HISTORY/BACKLOG/PENDING→PLAYBOOK)约 19.1 万字符,其中台账三件约 85% 是时间线叙事而非当前规范;AGENTS.md 状态段是 557 字编年史,HISTORY 单行最长 1,625 字节,同一坑在 AGENTS/PLAYBOOK 逐字双份维护。编年史混进规范文档,评审 Agent 反复把已裁决事项当新发现提出,每批复核「修 N 驳 M」,驳回结论又写成新叙事灌回文档——自我强化的评审污染循环,用户定性「这样项目走不动」。

## 决策

1. **规范与叙事分离**:规范文档(AGENTS/基线/合同/规格)只写当前有效的规则与事实;历史叙事(动因/评估/复核过程/编年史)只进 git 提交说明与 HISTORY 单行,不进规范文档正文。
2. **HISTORY 单行制(2026-09-08 起新行生效)**:一行 = `批次 | 日期 | tag | 验证状态 | 一句话要点`;旧行不重写(历史不篡改)。
3. **SETTLED 唯一查重清单**:`milestones/SETTLED.md` 收拢全仓「用户裁决/刻意设计/已驳回意见/引文纠错」(一行一条带出处,收拢自 HISTORY/BACKLOG 行内注记与历次评审台账);评审出新意见前必须先查重;主代理每驳回一条当场补行;结论被推翻时加「已废止」标注并写新行,不删旧行。
4. **评审必读入口**:以 AGENTS.md「评审纪律」节为唯一入口——AGENTS → 基线对应章节(架构=§1-§17,流程=§18-§19)→ BACKLOG 未结项 → SETTLED 查重;台账(HISTORY/PENDING)与辩论转录是记录不是评审对象,不主动通读。
5. **去重单源**:同一坑/事实只在唯一权威文件维护(高频坑=PLAYBOOK;当前版本=AGENTS 一行+HISTORY 表尾),其余位置只留指针不复制正文。

## 后果

- 评审必读路径从约 19.1 万字符降至约 4 万字符(台账三件移出必读,SETTLED 约一万字符替换;基线按章节选读)。
- 重复评审意见的机制性根源被切断:新意见须过 SETTLED 查重;驳回成本从「写进叙事等待下轮被翻出」降为「补一行索引」。
- 旧文档不追溯重写;冗余随自然修订逐步消化。
- 合同/代码/基线正文零变更:本 ADR 属流程纪律,锚定 AGENTS.md 与 milestones/SETTLED.md,故无基线正文熔入项。
