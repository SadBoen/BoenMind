# ADR-0027: 文档极简纪律——仓库只存规范、方向与欠账(过程文档交付即删) 
- 状态: Accepted(用户 ) - 日期: - 关联: 修订 ADR-0015(文档体系整理:三附页收敛为台账二件,时间线文件 HISTORY 撤销);细化 ADR-0026(规范与叙事分离的终局手段从「隔离」升级为「删除」);推翻 ) - 原理: 仓库内任何文件都会被 LLM 评审打开——不打开不知道它是什么,打开即污染上下文。隔离与分级挡不住「打开」这个动作,唯一根治是让文件不存在;已落实到框架的内容,代码+合同+基线即全量记录,过程副本没有留存价值。 
## 决策 
1. **入库白名单**:仓库文档只允许四类——①当前框架与功能的规范(基线/合同/ADR/PLAYBOOK/各 README/INSTALL);②以后的框架与功能(候选队列、选装参考);③欠账与裁决(BACKLOG/SETTLED);④机器消费件(validate.py/CI 读取的 golden-traces、invariants、m0)。 2. **过程文档交付即删**:实现规格、回看/review、结算表、辩论转录、外部验证报告、时间线(HISTORY)、已清零裁决队列(PENDING)——。本批删除 39 份()。 3. **交付全史=git**:tag 记发版点,提交说明记动机、范围与验证结果;不再维护任何时间线文件。 4. **批次生命周期(新惯例)**:开工写《实现规格》(临时工件)→。 5. **评审纪律不变**(ADR-0026):必读清单=AGENTS→基线对应章节→BACKLOG→SETTLED;可打开的文件面收敛到白名单,污染源物理消失。 
## 后果 
- 全仓 .md 92→53 个;评审 Agent 可打开的文件只剩白名单。 - 保留文件中指向已删文件的旧引用,统一按「溯 git 史」口径就地注记;旧 ADR 正文内的此类链接按硬纪律 3 不改,由本 ADR 统一覆盖。 - SETTLED 中与删除相抵的留档取舍条目,按其自身规则加「已废止」标注并写新行。 - 一切删除均可自 git 历史恢复;GitHub Release 资产不受影响。
