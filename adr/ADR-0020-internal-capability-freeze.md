# ADR-0020: 内置能力冻结与执行载荷纪律

- 状态: Accepted(用户 2026-09-03 复核裁决)
- 日期: 2026-09-03
- 关联: ADR-0005(万物皆插件与安全不变量四判据)、ADR-0006(权限以合同显式化)、ADR-0016(Skill v0.2 wasmtime 执行面)、ADR-0017(context-mode)、ADR-0019(system.exec 审批工具)、基线 §4.1/§12.3/§13.5
- 背景: 2026-09-03 外部 LLM 架构评审(13 项)经逐条实物复核后,用户裁决修复;本 ADR 闭合其中「system.exec 绕过 §13.5/四判据未成文」的程序性欠账(评审 #1/#6),并把 2026-09-03 当日对话裁决的「内置固化=1」方案制度化。

## 决策

### 1. 内置 Capability 清单封闭(内置冻结)

宿主进程内编译注册的 Capability 清单**就此封闭,不再增长**:

- 生产工具:`system.exec`(唯一;审批类,ADR-0019);
- 内核私有:`model.invoke`(不进对话工具面);
- 管线演示/测试桩:`system.echo`、`system.counter.bump`、`system.notes.write/delete`、`system.mail.mock_send`、`system.danger.purge`(M2-M4 管线五档风险标本,仅测试与演示用途)。

此后一切新能力一律以 **MCP 插件**(重工具,独立进程)或 **Skill 脚本**(轻工具,待 wasmtime)交付。范本:code-tools 随包官方插件(2026-09-03,search/read 直通、write/edit 审批,allowed_roots 沙箱)。

### 2. system.exec 的诚实定性:用户裁决的过渡态例外

按 ADR-0005 裁决 1,新增内建机制须通过安全不变量四判据,否则必须给出「为何不可做成 Provider」的证明。`system.exec` **不满足四判据任一项**,且理论上可做成 Provider——按纪律它不该是内置。保留它的真实依据是用户两次明示裁决(2026-09-02「按常规设计一次性做到日常可用」;2026-09-03 复核对话再确认「内置固化=1」),技术论据为**过渡态代价分析**(非永久正当性):

1. **回合取消强杀**:命令进程须与 turn 同生命周期,`kill_on_drop` 保证取消/超时必杀;跨进程形态(外部 MCP)取消只能发 `notifications/cancelled` 尽力通知,卡死命令可能失控(2026-09-03 外部评审亦确认此差别);
2. **审批-执行同进程**:无跨进程通知降级,宿主对执行链有完整控制权与收据;
3. **零进程开销**:省每插件一常驻进程与握手(日常调用毫秒级差异,被 LLM 秒级延迟淹没——非主因,如实记录)。

**终局路线**:`system.exec` 的行为可由 ADR-0016 WASM 脚本管线等价表达(进程内+沙箱+强限额)。WASM 面交付时回看本例外,届时迁移动机、成本与 kill 语义等价性一并裁决;迁移前本 ADR 即其合法性与边界的书面凭证。

### 3. 开内置清单判据(未来任何新增的前置)

提案新增内置 Capability 必须书面论证**同时**成立:

1. 该能力需要宿主强控制权(进程强杀/资源限额/特权系统调用),且 MCP 进程形态无法表达;
2. 四判据(ADR-0005 裁决 1)逐项核对并留痕;
3. 举证责任在提案方(基线行197 沿用),交付压力不得豁免;清单变更按基线 §13.5 处理。

### 4. 执行路径收敛

宿主侧命令/代码执行面收敛为两级:内置 `system.exec`(过渡,见条款 2)与 ADR-0016 WASM 管线(终局)。ADR-0017 context-mode 的执行模块如重新启用,其执行工具 manifest 必须按 destructive 提级至审批,并在插件文档明示「非沙箱宿主执行」;不得以与 WASM 同等的口径描述其安全边界。

### 5. 数据面载荷禁令

ADR-0001 数据面快路径(高频瞬态流)仅可承载**媒体/文本增量**;禁止承载命令或能力调用语义的结构化载荷,数据面消费者不得解释执行任何结构化指令。能力调用永远走 Broker 七步管线。此条为前瞻防御(现状数据面为模型 token 流直连聊天 UI,无执行型消费者;外部评审 #4 复核定级 P3 文档加固)。

## 条件与验收

- 内置清单以本 ADR 为封闭清单权威;任何新增须携带条款 3 论证并发新 ADR。
- WASM 执行面(Skill v0.2 第二步)交付里程碑的回看,必须复核条款 2 的过渡态例外是否延续(证伪即触发 exec 迁移裁决)。
- 外部评审 2026-09-03 的 P1 修复(门户墙收紧、插件 sha256 完整性校验)随本 ADR 同批落地;文档加固批(L0 豁免能力级清单、恢复 RTO、阶段二编排空窗语义、MCP 只读注解信任)登记 BACKLOG。
