# ADR-0030: 审批裁决后台化——权限模式为服务端会话状态 
- 状态: Accepted（用户 ） - 日期: - 关联: ADR-0001（Broker 唯一裁决）、ADR-0006（权限以合同显式化）、ADR-0019（system.exec 审批类）、ADR-0028（熔断硬停）、基线 §15、issue #42（重定义后本条即其决策文档）、issue #25（审批无人在线提醒） 
## 背景 
权限模式（ask/plan/yolo）的**状态与自动裁决均在前端网页**， 
1. 模式存于浏览器 localStorage（webapp `storage.ts` PermissionMode），浏览器级全局、不按对话记、服务端不知情； 2. "自动放行"由前端执行（`runtime.tsx` 流内+轮询双通道 `permMode==="yolo"` 全量 approve）；服务端无任何自动裁决逻辑——网页关闭即 yolo 失效，任务滞留审批等待环（400ms 单写者通道）； 3. `/admin/approvals/{id}/respond` 仅收 `{decision, scope}`，无来源字段——审计不可区分人工批准与前端自动批准； 4. yolo 自动批准对能力无过滤（审批队列内全量放行）。 
用户裁决（）：网页只是模式选择器（开关/值选择器），**模式状态与自动裁决必须在后台**；每个新对话默认要审批。 
## 决策 
1. **模式为服务端会话状态**。PermissionMode（ask|plan|yolo）成为会话的服务端字段：会话创建默认 ask（新会话默认值可配，默认 ask）；模式变更经指令端点进入单写者通道执行并落审计（时间+前后值）；浏览器 localStorage 遗留值迁移后忽略。按对话各记各的（用户口径 1）。 2. **裁决在服务端执行**。审批类调用到达裁决点时由运行时按会话模式裁决：ask → 等待人工（现状不变）；yolo → 服务端立即放行，收据与审计标注 `auto`（与人工可区分，补来源字段）；plan → 现状无独立语义（审批行为等同 ask），随本决策一并收编服务端，语义不变（用户口径 3）。 3. **放行范围 = RequireApproval 全体，硬拒绝不动**。yolo 仅自动放行 Broker `Decision::RequireApproval` 的调用；`Decision::Denied` 两类——`UnknownCapability`（能力未注册/binding 不存在）、`NoGrant`（无 Grant 且不满足直通，ADR-0006）——**无审批出口，不因 yolo 放行**（用户口径 2）；外圈硬停语义不变：同命令同参 10 次熔断+轮数安全网（ADR-0028）、预算硬限 blocked、意图硬门控。此语义与现状前端行为等价，仅执行层由网页搬回服务端。 4. **前端降级为选择器**。模式按钮改为"发指令+读服务端状态"，删除前端自动批准逻辑；#25 无人在线提醒保留（ask 模式仍需人工在线）。 5. **合同面只增**。会话模式字段、模式变更指令、来源审计字段、wire 事件按合同"只增不破"追加（Minor）；错误码如需新增与注册表同步（CI 比对）；状态迁移只沿 core-transitions 既有边。 
## 后果 
- 关闭/更换网页不影响 yolo 在跑任务；多设备模式一致（唯一权威在服务端）。 - 审计可区分人工批准与模式自动放行（respond 增来源字段，服务端放行天然标注）。 - ask 语义不变：仍需人工在线；#25 提醒继续有效。 - 不触碰 ADR-0006 硬拒绝边界与 ADR-0028 熔断——yolo 不获得越权通行证。 - 原issue #42"扩招"字面诉求由决策 3 覆盖（RequireApproval 全体本就全量放行，无需再扩）。 - 实施分三批：合同增字段 → 服务端裁决+审计 → 前端选择器化；每批全量门禁。收口时熔入基线正文并标注本 ADR；`docs/architecture/decisions.md` 同步增"审批裁决权在服务端"条目（15 条上限，届时淘汰最久未撞条目）。
