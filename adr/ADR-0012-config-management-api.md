# ADR-0012:配置管理 API——用户可改配置一律走成套 CRUD

- 状态: Accepted(2026-08-30)
- 决策类型: API 面与存储口径裁决
- 来源: 用户裁决(2026-08-30,M10 立项时):「每个配置文件(允许用户修改的
  这种)应该要有增删改查操作」;背景为 dsh 设置界面接通模型配置的需求。
- 关联: ADR-0006(权限以合同显式化)、ADR-0009(部署与 Surface)、M10 规格
  (S1)、D-M3-1(web 改版线)。

## 背景

模型接入配置此前只有启动 env 一条路(BOEN_MODEL_*),没有「界面保存配置」的
通道;web 设置表单因此无法接通。若为模型配置单开一个一次性写入接口,则每个
后续可改配置都会各开各的口子,API 面碎片化。用户裁决:后端缺的是一块正经
能力——配置管理 API,凡允许用户修改的配置一律有成套 CRUD。

## 决策

1. **统一方法族**:`config.list / config.get / config.set / config.delete`
   四方法(Minor 增发,wire/config.v0_1)。配置节 = 命名空间(ns)+ 数据目录下
   一份人可读 JSON(`config/<ns>.json`)。新增配置节 = 注册 schema + 字段校验,
   不再新增方法。
2. **优先级与生效**:逐字段「配置文件 > 启动 env > 内置默认」;服务器启动装配
   与 config.get 共用同一合并函数(单一真源);变更落盘后于下次启动生效(v0;
   热生效留后续)。
3. **密钥口径**:secret 字段(如 apiKey)明文只落配置文件(与既有
   `.secrets/dev.env` 明文同级,不倒退);运行时凭据仍播种进加密 Secret Store
   (INV-5 面不变);API 回显恒打码(values 中 null + secret_set 标记);
   config.set 对 secret 缺省/null/空串 = 保持不变,清除须显式 delete。
4. **双通道同一实现**:`/rpc/config.*`(Bearer 鉴权,合同方法,CLI 等表面可用)
   与 `/api/config.*`(web 界面喂食口,随 dsh 协议公开挂载)。公开通道是
   **已登记欠账**:公网监听前必须补鉴权(ADR-0009 T-13/T-14 前置不变)。
5. **层界**:配置管理属服务器层(bm-surface-http),不经 RuntimeHandle,
   后端核心零改动。

## 后果

- 正面:配置面一次成型,模型配置是第一个受益节;界面、CLI、未来表面共用
  一套配置 API;「界面保存 → 重启生效」语义简单可信。
- 代价:配置文件与 env 双源并存,需要优先级规则(已定);公开通道在鉴权补齐
  前仅限本机自用。
- 回退:若未来配置需要审批/多用户语义,发新 ADR 增发,不影响本决策的
  存储与合并语义。

## 条件与验收

1. validate.py 全绿(四方法入册,只增不破)。
2. config.* 方法级测试全绿(打码、留空不改、删除、非法值拒绝、双通道一致)。
3. M10 浏览器实测:表单保存 → 重启 → 生效链路真实走通。
