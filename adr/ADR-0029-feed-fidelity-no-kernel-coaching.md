# ADR-0029: 回喂忠实性原则——内核只回事实,话术出内核 
- 状态: Accepted(用户 ) - 日期: - 关联: ADR-0022(原生工具协议还原,废除负向禁令的同源纪律)、ADR-0028(限制全零);对照系 = Hermes/DSH/pi/Codex/Claude 五家源码取证(报告 `.tools/limits-reform-20260908/INTERFERENCE-COMPARE.md`,不入库溯 git) - 背景: 长任务对照取证发现,五家框架对工具失败/超时一律**附带已捕获输出与真实错误原文**;而 BoenMind 用「工具执行超时」四个字替代全部现场、provider 原始错误在连接器层被剥成枚举码(detail_ref 恒 None)、熔断/触顶时模型的调用凭空蒸发、内核还会代写 assistant 终稿冒充模型入台账。同时内核硬编码了多处指导性话术(工具纪律段、审批「请向用户说明」、工具描述「优先用 X」等)。用户裁定:干预的唯一合法形态是事实;指导类文本若要有,只能经插件通道以可区分方式注入。 
## 决策 
### 1. 回喂只承载事实(新增合同不变量 INV-13) 
内核写入 tool 角色消息与错误信封的内容只承载事实——工具原文、真实错误(经凭据脱敏)、未执行原因。落地: 
- **失败回喂附真实错误**:`工具调用失败({error_code}): {消息}`、`工具执行失败(error_code=X) {消息}`(审批分支同),废除「请向用户说明」类教练话术。 - **「工具执行无应答」废除**:调用层直接失败时如实转述 CoreError(error_code+消息),不再以占位文案掩盖真实死因。 - **超时文案带事实**:`工具执行超时:等待 N 秒未收到执行结果,工具未执行`;审批超时同构。 - **幂等抑制如实告知**:等价请求幂等返回时,回喂注明「本次未重复执行(等价请求幂等返回原结果)」,模型不再误以为本次真实执行。 
### 2. 错误原文保真(合同 Minor 增发) 
- `InvokeResponse::Failed` 与 `WireError` 增发可选 `detail: Option<String>`(序列化非空才出字段;envelope schema 增补 `detail` 属性,maxLength 2000)。 - openai_http:HTTP 4xx/5xx 响应体经**凭据脱敏**(本请求凭据值替换为 [REDACTED])与 2000 字符截断后随 `detail` 透传;`模型降级链耗尽` 的用户可见消息追加该细节(500 字符上限内截断)。INV-5 纪律不变——detail_ref 恒 None 的旧口径系过度解读, INV-5 只要求凭据明文零出现,脱敏即可满足。 - glm 连接器暂不抓响应体(detail 恒 None),随用随补。 
### 3. 不再代替模型发言 
- 熔断/触顶拦截的调用**不再凭空蒸发**:逐个回喂事实性结果 `本调用未执行:{原因}。`(原因=防空转熔断/轮数上限),模型、日志因果链完整;回合就此收束,不重调模型。 - **内核代写 assistant 终稿废除**:原「(检测到连续 N 次…)」「(本回合工具调用已达 N 轮上限…)」「(工具调用已执行完成…)」三段不再作为终稿入台账冒充模型发言;收束原因只在触发点经 ProviderDelta 上屏(UI-only)。assistant_final 轨迹事件只在模型真有话时记录。 
### 4. 硬编码话术全清(用途认可,归宿=插件) 
清除清单:①「工具纪律」意图门控 System 段(spawn.rs,SETTLED §2-10 的硬编码形态自本 ADR 废止);②jobs 摘要「完成后用 system.job_output 收取结果」指导句;③工具描述四处「优先用 X/建议先 X」(system_exec、fs.read/fs.write/fs.edit);④fs 搜索超时 note 的「(可缩小范围/加 path_pattern 重试)」括号指导;⑤审批分支「请向用户说明」。 
保留的非话术事实注入:工作目录声明、后台作业清单、技能指令(用户配置内容)、审批语义说明(「调用需用户批准后执行」=运行时事实)、历史占位符。autorun 指令模板属 Task 自动驾驶的协议定义,非干扰,不在清除之列。 
## 后果 
- 合同 Minor 两笔:WireError/InvokeResponse 增发可选 `detail`;envelope schema 增补 `detail` 属性。INV-13 入 M1 不变量表(检查=构造点审计+脱敏边界测试)。 - 行为变化提示:升级后模型将看到真实错误原文(含网关限流/配额类死因),用户在「回合执行失败」处也能看到细节;熔断/触顶不再无声。 - 已知边界:输出超限的落盘交接(五家均有)涉及 provider 存储通道设计,本批未做,登记 BACKLOG;提醒/指导类文本的插件注入通道(承载被清除话术的合法归宿)登记 BACKLOG 待设计。 - glm 连接器 detail 暂恒 None。
