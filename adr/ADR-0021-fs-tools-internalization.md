# ADR-0021: 文件工具集内置化(fs.*)与 code-tools 插件退役

- 状态: Accepted(用户 2026-09-04 复核裁决)
- 日期: 2026-09-04
- 关联: ADR-0020(内置能力冻结,本 ADR 修订其范围)、ADR-0019(system.exec)、ADR-0018(工作区注册表)、ADR-0006(权限显式化)、ADR-0011(App=stdio MCP)
- 背景: code-tools 随包插件(2026-09-03,commit a6f9959)交付当晚,用户试用后提出两点:①「我本以为这是非常常用的工具,你会将其内置的。我希望内置」——查/读/改是 AI 基础手脚,外部子进程形态一断(子进程被杀/管道卡死/沙箱未配)AI 立即残废,且开箱即用不应要求「扫描-批准」流程;②「不应该限定为 code」——md 笔记、文档、配置文件同需查读改,插件名误导模型心智。对内置化方案(改名 fs.*、收编内核、下线演示假桩)用户明示「完全同意」(2026-09-04 凌晨会话)。

## 决策

### 1. fs.* 四件收编内核内置

code-tools 插件的四个工具以内核内置能力交付,命名升级为通用文件工具:

| 能力 | 审批分级 | 说明 |
|---|---|---|
| `fs.search` | read-only 直通 | rg 同款引擎(grep-searcher/grep-regex 库内嵌,ripgrep 本体同款核心 crate) |
| `fs.read` | read-only 直通 | 带行号 + offset/limit 分页 + 智能截断 |
| `fs.write` | required 审批 | 新建/整文覆盖,自动建父目录 |
| `fs.edit` | required 审批 | 精确字符串替换(唯一命中才动手;CRLF 自动兼容;非 UTF-8 拒改) |

形态 = 内置异步能力(provider id `builtin.async`,同 system.exec;search 的全树遍历不得占死单写者循环,执行体走 spawn_blocking)。

### 2. 沙箱根 = 工区注册表(ADR-0018)

`allowed_roots` 由插件私有配置改为**工作区注册表**(`<data>/config/workspaces.json`)驱动:注册表内全部已登记目录为白名单根,注册表为空回落工作区浏览根(`BOEN_WORKSPACE_DIR` / `<data>/workspace`)。每调用重建根表(注册表增删免重启生效)。防逃逸机制不变:词法归一(`.`/`..`)+ 最深已存在祖先 canonicalize + 组件级前缀比对(防 `BoenMind2` 同名前缀)+ Windows `\\?\` 前缀剥离。

### 3. code-tools 插件退役

`plugins/mcp/code-tools/` 源码删除(git 历史保留),release 工作流移除其门禁/构建/打包。逻辑无损移入 `bm-providers::fs_tools`(含原 20 项单测移植)。**已升级安装的迁移**:旧版遗留的 `code-tools.exe` 与 `mcp.json` 条目不自动清理,在插件中心「移除」或手动删除即可(不清理也不影响 fs.* 使用,仅多一个离线条目)。

### 4. 对 ADR-0020 冻结范围的修订

ADR-0020 条款 1 的封闭清单中,生产工具由「仅 system.exec」修订为「system.exec + fs.search/fs.read/fs.write/fs.edit」。本修订依据:

1. **用户主权裁决**:ADR-0020 本身以「用户两次明示裁决」为 system.exec 的合法性与边界凭证;本次用户以同等效力明示(「我希望内置」「完全同意」),冻结清单的修辞性质相同;
2. **可靠性论据**:查/读/改是对话 Agent 每回合依赖的基础手脚,进程隔离的可用性代价(子进程单点)对其不成立——这与 ADR-0020 为 exec 保留的「回合取消强杀」同属宿主强控制权诉求(文件工具弱于 exec,但同享内置形态的可靠性红利);
3. **心智正确性**:工具名即模型心智,`code-tools` 使模型自限编码域;`fs.*` 如实表达通用文件域。

冻结纪律本身不变:清单仍封闭,此后任何新增仍须 ADR-0020 条款 3 论证并发新 ADR;内置能力增长速度仍受该程序约束。

## 条件与验收

- 对话工具面出现 `fs__search`/`fs__read`(直通)与 `fs__write`/`fs__edit`(审批卡),模型可自发调用并回喂;
- 越界路径(逃逸/白名单外绝对路径)一律拒绝并有可读错误;
- 插件中心内置列表与白话说明一致(model.invoke 标注「内核私有·模型调用通道」);
- workspace 版本随下次发版 bump;C4 拓扑零改动(fsProvider→fs.* 线为模型既有设计,本次为实现对齐)。
