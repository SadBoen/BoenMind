# AI 记忆管理策略

> `.ai/` 目录文件数控制在 15 个以内，防止上下文污染；每个事实只有一个唯一源。

## 分层（不重复维护）

1. **坑 / 环境怪癖** → 唯一源 `docs/development/PITFALLS.md`（本目录只留指针，不复制正文）
2. **用户偏好**（如"不主动操作VPS"、"发版需用户明示"） → `.ai/context.md`
3. **最近工作** → 交付史 = git（tag + 提交说明），不另立文件（ADR-0040）

## 删除规则

- **"XX批次已交付"完整记录**：不写，归 git 提交说明（ADR-0027/0040）
- **驳回理由详细证据**：不写，决策结果已在 `docs/architecture/decisions.md`
- **过程文档 / 回看报告**：不写入记忆，落 `.work/`（gitignore，交付即删）

## 维护时机

- 每次会话结束前，若有新坑 / 新偏好，合并进对应唯一源（不新建文件）
- `.ai/` 超过 15 个文件时，删除最久未被引用者
- 定期（里程碑收尾）review 一次，删除已不适用的条目
