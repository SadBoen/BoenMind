# M2 开工前置:ADR-0003 / ADR-0004 验收条件结算表

> 依据 AGENTS.md 进度区:M2 开工前须结算 ADR-0003/0004 相关验收条件。
> 本文逐条清点两份 ADR 的「条件与验收」,分为四类:
> **[已闭合]** 基线/前序里程碑已完成;**[M2 落地]** 由 M2 实现结算(已转成规格约束);
> **[顺延]** 归属后续里程碑,注明;**[待裁决]** 需用户拍板,记入 `milestones/PENDING.md`。
> 本表是《M2 实现规格》的输入;规格起草时须把 [M2 落地] 项转写为设计与验收条目。

## ADR-0003(L0 控制面与 generation 升级回滚)六条件

| # | 条件摘要 | 分类 | 结算说明 |
|---|---|---|---|
| 1 | L0 最小能力集,禁止承载迁移语义解析 | 顺延 | L0 进程属阶段二控制面,M1-M8 里程碑序列未含 L0 实现;M2 的约束面 = 不得把迁移语义塞进任何"底座"组件,M2 规格遵守即可 |
| 2 | active 指针自动回退两前提(格式未变 + 无分叉) | 顺延 | 无 generation 即无指针回退;但其对偶要求——**状态迁移必须走版本化迁移合同 + expand-contract**——转为 M2 落地项 |
| 3 | 完整双代际流程仅限 L1 Major | 顺延 | 同上,M2 无升级路径 |
| 4 | 自动回滚前须定义健康合同(probation 判据) | 顺延 | M2 无自动回滚;判据定义留到升级路径存在的里程碑(阶段二) |
| 5 | 触及真实 Provider 的升级须副作用可证明性 | 顺延 | M2 无触及真实 Provider 的升级 |
| 6 | outcome_unknown 处置协议(禁自动重放/外部核验/用户裁定入口)须落地 | **M2 落地** | 即基线 M2.6;M2 规格必须包含:outcome_unknown 只能经「外部核验 / 用户裁定 / 显式恢复流程」结束(INV-10 已有测试形态);M1 的状态机 guard 与 fuzz 已承载一半,持久化后的恢复流程补全另一半 |

## 转入《M2 实现规格》的硬约束清单(起草时逐条转写)

1. SQLite 规范状态 + Append-only Event Log 单写者;投影只自事件日志重建(0004-1)。
2. 快照/压实为强制机制,含触发策略与压实点语义(0004-2)。
3. 状态库 schema 版本化迁移 + expand-contract;禁止押注指针回滚(0003-2 对偶)。
4. outcome_unknown 恢复流程:查询/认领/补偿,禁止自动重放(0003-6 / 0004-4 / INV-10/11)。
5. 写入 API 预留 CAS/epoch 条件写入形态(0004-3 底座)。
6. 瞬态/遥测写路径与规范状态分离(0004-7)。
7. 四项混沌测试按 PENDING D-M2-1 的适配映射进入 M2 验收清单(0004-8)。
