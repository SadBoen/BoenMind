# W3 实现规格:主题系统(两级换肤)——需求登记版

- 序列:WEBUI W3(前置:W2 设置中心完成后定稿动工;依赖 W2 的设置页骨架
  与「外观」导航位)
- 状态:**需求已由用户定义(2026-09-01 口述),本文为登记版;范围细节与
  各主题设计稿待 W2 验收后与用户定稿**
- 用户原话要点:「W3 主攻风格切换,风格自定义为两级:一级是主题(古典/
  现代/卡通/玻璃),二级是每个主题有设置项(配色、透明度、背景这些)。
  不是所有主题都有相同的设置,比如透明度就只有玻璃主题有」

## 1. 需求(用户意图结构化转写)

1. **一级:主题预设**4 个,内置:
   - 古典:衬线字体、纸墨/暖色调、传统版式
   - 现代:即 W1 现状(浅色、细边框、专业开发工具风)
   - 卡通:大圆角、明快配色、活泼氛围
   - 玻璃:半透明毛玻璃(blur)、通透层次
2. **二级:主题内设置项**,每个主题自带清单,项集**不必相同**:
   - 例:配色(主色/强调色)、背景(纯色/图)
   - 例:透明度——**仅玻璃主题有**
3. 换主题 = 全站换肤:三栏、对话、设置、消息全部随令牌切换
4. 主题选择与各主题设置项持久化(重启保持)

## 2. 技术形态(实现时定稿)

- 底座 = W1 已建立的 CSS 设计令牌(styles.css :root 变量表);主题 =
  令牌预设覆盖 + 少量主题专属样式类
- 每主题「设置项清单」= 该主题自带的 schema(项名/类型/默认值/取值域),
  设置页据此动态渲染表单——**每主题 schema 不同**正是用户要求的核心
- 持久化:W3 先 localStorage,随 W 系列配置中心(§W2 恢复 config API)
  收编为服务端配置
- assistant-ui 关系:主题系统为**自有组件**(纯令牌层,不触碰对话原语);
  assistant-ui 原语自身无样式假设,天然随令牌换肤

## 3. 主题设置项清单(初稿,定稿与用户逐项过)

| 主题 | 设置项 |
|---|---|
| 全部通用 | 主配色 |
| 古典 | 衬线字体强弱、纸色深浅、行距 |
| 现代 | 紧凑度、强调色 |
| 卡通 | 圆角大小、配色活泼度、表情装饰开关 |
| 玻璃 | **透明度**、模糊强度、背景图、背景暗化 |

## 4. 用户补充裁定(2026-09-01 深夜口述,已定)

1. **文字大小与主题无关**(属全局/偏好设置,不入主题 schema);
   **文字字体可入主题**:如卡通主题可设可可爱爱的字体
2. **背景支持自定义图片**,但按主题开启:如「现代」主题**只能改配色,
   不开自定义背景**;有背景项的主题才能用自定义图
3. **实时预览**:能做到就做(改设置项即时生效)
4. **视觉稿来源**:找技能/专业网站出稿;优先摸爬
   assistant-ui showcase(www.assistant-ui.com/showcase),盘点可
   直接利用的成品/半成品样式(用户明示:直接利用,效率优先)

## 5. 验收门(沿 W 序列固定流程:浏览器 MCP 可视化验收)

1. 四主题一键切换,全站(三栏/对话/设置/消息)同步换肤,刷新保持
2. 各主题设置项动态渲染正确(玻璃见透明度,其他主题不见)
3. 设置改动即时生效且重启保持
4. 对话闭环回归(banana 实测)不退化
