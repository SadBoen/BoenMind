# M4 开工前置:ADR-0001 / ADR-0002 验收条件结算表

> 依据 AGENTS.md:M4(Capability、Broker、权限和审批)开工前须结算
> ADR-0001(Registry/Broker/Bus 三权分立)与 ADR-0002(Task 规范状态、
> Butler/Coordinator)的验收条件。分类同 M2 前置:
> **[已闭合]** / **[M4 落地]** / **[部分落地]** / **[顺延]**。
> 本表是《M4 实现规格》的输入;规格起草时须把 [M4 落地] 项转写为设计与验收条目。

## ADR-0001(三权分立)七条件

| # | 条件摘要 | 分类 | 结算说明 |
|---|---|---|---|
| 1 | Broker 策略预编译为 O(1) capability 查表;证伪判据=p99/队头阻塞/故障半径三测试 | **M4 落地** | Broker 实现核心验收项;查表结构 + 三项性能/故障测试进 M4 验收 |
| 2 | binding_epoch + provider_instance_id 基线增补(授权-执行-审计三方一致) | **M4 落地** | 合同 Minor:capability 调用凭证增列 epoch/instance 字段;测试=授权后强制切换 binding,验证三方一致 |
| 3 | Bus 事件 schema 机器校验 + 持久生产者白名单 + 伪造/乱序注入 | 部分落地 | M2 已有:注册表键集断言 + 单写者结构即白名单;M4 补:命令语义事件持久化拒绝 + 伪造/乱序故障注入测试 |
| 4 | 数据面分流四测试(无授权拒绝/审计归属/吞吐解耦/崩溃对账) | **M4 落地** | lease 签发 + 通道准入拒绝 + 审计回写测试;吞吐解耦项以 mock 通道计时;M7 真实 Provider 后复测 |
| 5 | 副作用 Provider 合同(收据/幂等查询/outbox 顺序/指标上限) | 部分落地 | M4:事务性 outbox 结构 + 回归指标定义 + 通用禁止盲目重试;首个真实副作用 Provider(M7)实证 |
| 6 | 降级路径:Event Bus 暂停时核心状态可提交;瞬态/持久写路径物理隔离 | **M4 落地** | 瞬态不落盘 M1 已有;Bus 暂停语义(Broker 授权照常、事件追加失败不阻塞状态提交)为 M4 实现项 |
| 7 | 架构守护 CI 常驻:三种侵蚀即测试失败(Bus 当 RPC/命令混入事件流/混层缓存) | **M4 落地** | 守护测试三件套进 CI;L0 兜底边界不被突破(不得增设特权降级通道) |

## ADR-0002(Butler/Coordinator)六条件

| # | 条件摘要 | 分类 | 结算说明 |
|---|---|---|---|
| 1 | Grant 规格闭环:audience/action/资源谓词/过期/撤回版本/不可再转授/父授权哈希;Provider 调用点验证+幂等键 | **M4 落地** | Capability Manifest + Approval 持久对象承载;字段按下限清单实现(未决分歧的字段超集留扩展);M5 Domain Agent 出现后实证双路径 |
| 2 | 协调动词子树过滤 + safe/mutation 分级写入基线并在 Broker 调用点强制 | 部分落地 | safe/mutation 风险分级 = M4 Capability manifest 必备属性;子树过滤随 M5 Butler/Coordinator;未落地前子树外命令默认拒绝(与 ADR-0006 一致) |
| 3 | 注入回归用例量化阈值 + CI 门槛(untrusted→reversible+ 100% 升级;越权 100% 拒绝) | **M4 落地** | M4.8 input_trust 门控 + PI 用例集扩展;阈值按 ADR 建议(100%/100%)写入验收 |
| 4 | 双路径共享 Grant/幂等/脱敏/收据合同(统一前禁止双开) | **M4 落地** | 合同层统一在 M4 定义;「双路径」本身 M5 Domain Agent 落地时启用,启用前不存在双开问题 |
| 5 | Memory Service 接口阶段一规划(跨 Task 上下文) | 顺延(M4 规划位) | M4 规格预留 memory.* 接口位(基线 M5.7 已列);实现随 M5 |
| 6 | 幂等抑制审计证明(两次等价请求第二次被抑制,可从审计证实) | **M4 落地** | idempotency_conflict 错误码(M1 已备)+ 审计事件断言测试 |

## 转入《M4 实现规格》的硬约束清单(起草时逐条转写)

1. Broker 策略查表化(O(1)),七步管线仅逻辑拆分;三证伪测试(0001-1)。
2. 调用凭证固化 binding_epoch + provider_instance_id,授权-执行-审计三方一致(0001-2)。
3. 事件 schema 校验加固:命令语义拒绝持久化 + 伪造/乱序注入测试(0001-3)。
4. 数据面 lease 准入四测试;吞吐与 L2 单写者解耦(0001-4)。
5. 事务性 outbox(状态提交→审计→事实追加顺序)+ 回归指标上限(0001-5)。
6. Bus 暂停降级语义 + 瞬态/持久物理隔离(0001-6)。
7. 架构守护测试三件套进 CI(0001-7)。
8. Capability Manifest 含 safe/mutation 风险分级 + Grant 下限字段集(0002-1/2)。
9. input_trust 门控:untrusted→reversible+ 100% 升级审批;越权 100% 拒绝,进 CI(0002-3)。
10. 双路径统一 Grant/幂等/脱敏/收据合同(单路径期仅定义不启用)(0002-4)。
11. 幂等抑制审计测试(0002-6)。

## 备注

- M4 无需用户预裁决项:两份 ADR 的条件均为技术可判定项;未决分歧
  (envelope 字段边界、委托凭证字段超集、预算预留深度)由实现规格
  按"条件给出的下限 + 可扩展"原则裁决并留档,超集演进不破坏只增纪律。
- M5 关联项(Butler 子树过滤、Memory Service 实现)已在 ADR-0002 条件 2/5
  标注归属,不随 M4 提前实现。
